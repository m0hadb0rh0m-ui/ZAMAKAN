# ZAMAKAN 2.1 — production pilot
## Delivered
- One-click combined MapLibre terrain and OSM/OpenFreeMap extrusions, DEM elevation and rendered-building height inspection, current model weather context. No survey-grade twin, real-time building telemetry, guaranteed global height data, or city-scale photogrammetry.
- CAP: existing strict CAP 1.2 parser, lifecycle and reference checks and NWS; additional fixed RSS adapters for Australia BOM, Germany DWD, India NDMA as listed in WMO RAA. Links to WMO SWIC, RAA, Meteoalarm and WWMIWS. RSS entries are not authenticated CAP and are not broadcast as official warnings. Source failures and empty feeds do not establish safety.
- Cloud Worker and D1 schema for the hosted pilot: trusted Sites identity, per-user preferences/favorites, explicit upload/download, origin validation, bounded payloads and optimistic version checks. Native/standalone app local SQLite accounts use the same contract. Separate credential-free web pilot; native cloud SSO is not integrated. A private pilot is not a public global service.
- Firebase Android source and opt-in topic subscription conditional on a proper Firebase configuration. A fixed research-test data notification only; no emergency push, private targeted delivery, or verified Firebase receipt without a configured account/project and devices.
- Protected manual production workflow takes signing certificates from environment secrets; verifies Android signature and Windows trusted Authenticode signature before artifact upload. No self-signed Windows certificates are presented as trusted. No secrets in source.
- Worker smoke test with separate identity records and SQLite D1 adapter, sync isolation, CSRF, stale revision, SSRF source allowlist, unsafe XML and payload validation. Previous full CI succeeded; new CI and physical operating-system tests must be confirmed.
## Release operations
1. Build: `npm ci && npm test && npm run build && node cloud/build.mjs && node tests/cloud-smoke.mjs`. Cloud assets are bundled for Sites Worker and do not enter Android native releases. Use D1 migration in `drizzle` on Sites deployment; server's SQLite data is managed separately.
2. Firebase: create/configure Android application `org.zamakan.earth` in your Firebase account; configure the Cloud Messaging HTTP v1 API; store base64 Android config as `FIREBASE_ANDROID_CONFIG_B64` in protected release environment. Never publish a service account. After explicit opt-in, operator runs `node scripts/fcm-test.mjs` with `FCM_SERVICE_ACCOUNT_JSON` from protected runtime (validate-only by default). `--send` sends a fixed test to the research topic. No arbitrary message API. Validate actual receipt on physical device.
3. Signing: protect the `production-signing` environment with required reviewer and trusted branch restrictions; use secrets ANDROID_KEYSTORE_B64, ANDROID_STORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD; authorized Windows certificate credentials WIN_CSC_LINK and WIN_CSC_KEY_PASSWORD. For organizations using hardware-backed/managed signing, adapt the workflow to that provider. Never create a public signing key, commit a keystore, or send keys in chat.
4. Security: use least-privilege secrets; retain backups and rotate; perform independent penetration test, verify rate limiting and authorization in real deployment, SBOM and dependency scan, device testing, CAP issuer trust and data-license review. No guarantee of absolute safety or comprehensive field validation.
